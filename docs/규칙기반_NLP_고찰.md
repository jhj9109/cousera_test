# 감성 분석과 정보 추출로 본 통계 기반 NLP와 규칙 기반 NLP

## 4-1은 어떤 과제인가

- **목표** — 뉴스 기사나 리뷰를 단어별 가중치 목록(TF-IDF 벡터)으로 바꾸고, 단어의 출현 빈도만으로 문서를 얼마나 잘 찾고 분류할 수 있는지 확인
- **검색** — 질의와 문서를 같은 방식으로 벡터화한 뒤 코사인 유사도가 높은 문서 5개 반환
- **분류** — 정답 범주가 붙은 문서로 분류기를 학습하고, 별도 테스트 문서의 정확도·F1과 오분류 사례로 어순·문맥을 놓치는 한계 분석

**4-2와의 연결** — 이번 과제에서도 출현 빈도로 감성어 후보를 고르지만, 개별 리뷰의 점수는 사람이 정한 사전과 부정·강조 규칙으로 계산. 날짜·금액 등의 추출 여부는 정규식과 값 검증으로 결정

## 감성 분석의 설명력과 유지보수 비용

| 리뷰 | 검출 결과 | 최종 점수 |
|---|---|---:|
| 영화가 재미없진 않아 | ‘재미없다’ −1점에 ‘않다’가 부정 규칙 적용 | +1 |
| 영화가 재미없는 건 아니야 | ‘재미없다’ −1점과 ‘아니다’ −2점을 별도 항목으로 합산 | −3 |

- **설명력** — 의미가 비슷한 두 문장의 판정 차이를 매칭 항목과 부정 횟수로 추적. [감성 점수 계산 코드](../src/korean_sentiment.py)
- **유지보수 비용** — ‘아니다’를 부정어로 추가할 때 기존 사전 점수와의 중복 적용까지 검토
- **사전 확장 효과** — 영화 표현 51개 추가 후 동일 규칙으로 NSMC 테스트 리뷰 1,000건 평가. 정확도 **68.2% → 70.2%**
- **회귀 사례** — 기존 오답 27건 개선, 기존 정답 7건 악화. 새 규칙이 해결한 문장과 새로 틀린 문장을 함께 확인. [평가 노트북](../notebooks/05_korean_sentiment_scoring_evaluation.ipynb) · [리뷰별 판정 변화](../data/outputs/sentiment_evaluation/review_scores_v001.csv)

## 정보 추출의 정밀도와 재현율

- **평가 표본** — 9개 유형 × 12문장 = 108문장. [07 평가 결과와 실패 원문](../notebooks/07_information_extraction_evaluation.ipynb)
- **정탐(TP)** — 예측 유형과 원문 시작·끝 위치가 정답과 모두 일치
- **정밀도** — 추출 구간 중 정답 비율 `TP / (TP + FP)`
- **재현율** — 정답 구간 중 추출 성공 비율 `TP / (TP + FN)`

| 유형 | 평가 결과 | 오류 원인 |
|---|---|---|
| 금액 | 정밀도 100%(7/7), 재현율 63.6%(7/11) | ‘5000원입니다’는 ‘원’ 뒤의 한글 때문에 미탐. ‘1.5억원’은 후보 탐색 후 원화 정수 검증에서 제외 |
| 날짜 | 정밀도 90.0%(9/10), 재현율 81.8%(9/11) | 모델명 ‘2024-12-31’은 달력 검증을 통과해 오탐. 제조일 ‘20240501’은 구분자 생략으로 미탐 |

- **형식 제약** — 잘못된 표기를 걸러내는 효과와 정상적인 표기 변형을 놓치는 비용
- **문맥 한계** — 형식과 달력이 모두 유효해도 모델명과 발매일을 구분하려면 주변 문맥 필요

## 모듈 분리와 확장 절차

| 모듈 | 입력과 처리 단위 | 결과·의존성 |
|---|---|---|
| 감성 분석 | Okt 토큰과 사전 항목 | 리뷰 전체의 감성 점수. JDK·Okt·감성사전 사용 |
| 정보 추출 | 원문의 문자 구간과 정규식 후보 | 유형별 정규화·마스킹 값. 파이썬 표준 라이브러리로 독립 실행 |

- **분리 이유** — 입력 단위·출력 목적·실행 환경이 달라 각 모듈을 독립적으로 실행·검증
- **정보 유형 추가** — `PATTERNS`에 유형명·정규식 등록 → `InformationNormalizer.normalize_<유형>` 정의 → 민감 유형은 `SENSITIVE_TYPES` 등록 및 `PrivacyMasker.mask_<유형>` 추가. 유형명을 기준으로 함수 연결. [추출기 구현](../src/information_extractor.py)
- **감성어 추가** — 학습 리뷰 빈도·용례 검토 → 단어·품사·점수·선정 이유 기록 → 04에서 확장 사전 새 버전 생성. 05의 비교 버전은 `LEXICON_VERSION`, 독립 시연은 `load_assignment_lexicon()`의 v001 사용. [04 사전 검토](../notebooks/04_korean_domain_lexicon_review_ui.ipynb) · [사전 로더](../src/korean_sentiment.py)
- **회귀 검증** — 같은 테스트·표본으로 변경 전후 비교. 07은 ID별 오탐·미탐, 05는 리뷰 ID별 예측, 06은 표현별 점수 확인. 개선·악화 사례를 기록하고 원인을 확인한 예문은 기대값과 함께 단위 테스트에 추가

## 접근법의 선택 기준

| 비교 기준 | 통계 기반 · 4-1 명세 | 규칙 기반 · 4-2 구현 |
|---|---|---|
| 적합한 작업 | 어휘가 비슷한 기사 검색. 주제 레이블이 충분할 때 로지스틱 회귀 또는 선형 SVM으로 새 기사 분류 | 개별 리뷰의 점수 산출 근거를 설명하거나, 일정한 양식에서 날짜·금액의 위치를 찾아 값을 정규화하는 작업 |
| 판단 근거 | 검색은 질의와 문서가 공유하는 단어의 가중치, 분류는 단어별 TF-IDF 값과 학습한 클래스별 계수로 기여도 확인 | 감성 분석은 매칭 표현·기본 점수·부정 횟수·강조 배율, 정보 추출은 일치 구간과 검증 조건을 직접 확인 |
| 도메인 변경 | 새 말뭉치에서 어휘·문서 빈도를 다시 추정. 분류는 새 도메인의 레이블로 성능 확인 | 새 표현·표기마다 사전이나 패턴을 수정하고 기존 정답에 미치는 영향 확인 |

- **어순과 부정 범위** — 단어 단위 BoW에서는 같은 토큰을 같은 횟수로 쓰면 순서가 달라도 벡터가 같음. 4-2는 ‘안 뻔하다’에서 ‘안’의 위치를 보고 −1점을 +1점으로 반전할 수 있지만, ‘재미없는 건 아니야’처럼 별도 사전 항목으로 잡히는 부정은 놓침
- **두 접근을 함께 쓴 사례** — 영화 리뷰에서 ‘여운’은 긍정 리뷰 130건, 부정 리뷰 6건에 등장해 검토 후보로 선정. 실제 용례를 검토해 +1점으로 등록한 뒤에는 새 리뷰에서 ‘여운’이 매칭될 때 그 점수를 계산에 사용. [후보 선정과 점수 예시](../README.md)
